Why TzdLang

核心特性与语言优势

融合动态脚本的高效开发流与工业级编译器的极限算力，构筑下一代通用语言基座

双层分级混合执行架构

代码优先在 Tier 0 字节码虚拟机 中极速执行，实现零等待冷启动；热点探测器智能捕获调用与循环回边，在后台工作线程无感触发 Tier 1 LLVM ORC JIT 深度编译为原生 x86_64 机器码。

超越 HotSpot 的极致性能

在多项工业级基准测试中超越 JDK 20 HotSpot：函数调用开销快 2.5 倍、嵌套循环快 1.7 倍、简单累加循环快 1.5 倍。无装箱原生 double worker 彻底消除递归与数值计算冗余。

原生 LibTorch 深度学习支持

语言内建 stdlib/torch/ 体系，无缝集成 C++ LibTorch 底层算子。提供 Sequential、Linear、ReLU、CrossEntropyLoss 等完整模型构建与自动微分接口，彻底告别 Python GIL 瓶颈。

现代面向对象与函数式融合

支持单继承、构造器级联 super()、虚方法多态、字段访问控制，同时拥有一等公民闭包（Lambda）、元编程注解（Annotation）、枚举与 switch-case 结构化模式匹配。

分代三色标记 SATB 垃圾回收

新生代采用 Bump Pointer Arena 块分配器，以 O(1) 效率极速分配对象且无内存碎片；老年代基于三色标记-清除算法并集成 SATB（原始快照）写屏障，保障并发标记期内存安全。

专业 VSCode 扩展与 DAP 调试

配套全套 VSCode 扩展（vscodePlugin/tzdlang），支持语法着色、智能代码补全、错误检查，以及基于 DAP 协议的断点命中、单步跟踪（Step In/Over/Out）、调用栈回溯与变量实时监视。

1. 变量声明与类型系统

TzdLang 提供动态类型声明（var、let、const），同时原生支持可选静态强类型（int、float、string、bool、void、ptr、数组 type[] 以及自定义类类型）。 

// 动态类型声明
var dynamicVal = 100;
let mutableVal = "Hello";
const PI = 3.14159265;

// 静态强类型声明（推荐用于高性能计算与 JIT 优化）
int count = 10;
string message = "System Ready";
float ratio = 0.75;
bool isActive = true;
ptr nativeHandle = null; // 指针类型 (ptr, pointer, hwnd)

// 冒号类型语法
var total : int = 500;

// 数组类型
int[] numbers = [1, 2, 3, 4, 5];
print("数组长度: " + len(numbers));
类型建议：在热点计算与密集循环中，显式声明静态类型（如 int、float）能够指导 JIT 编译器在 Tier 1 生成更高效的无装箱原生机器码指令。

2. 控制流程与循环语法规范

TzdLang 支持标准的条件分支与循环结构。请务必注意 for 循环的初始化表达式规则。

重要语法规则：for 循环的第一个表达式严禁包含类型名或 var 关键字！变量必须预先声明或直接赋值。 
// --- 1. 条件分支 ---
if (score >= 90) {
    print("优秀");
} else if (score >= 60) {
    print("及格");
} else {
    print("不及格");
}

// --- 2. For 循环 (正确写法) ---
// 正确：直接赋值初始化
for (i = 0; i < 5; i = i + 1) {
    print("索引: " + i);
}

// 正确：使用 ++ 自增
for (j = 0; j < 10; j++) {
    if (j == 8) break;      // break 中断
    if (j % 2 != 0) continue; // continue 跳过
    print("偶数: " + j);
}

// 错误写法 (语法解析器将报错):
// for (var i = 0; i < 5; i++) { ... } // 不支持！

// --- 3. While 循环 ---
var n = 0;
while (n < 3) {
    print("While计数: " + n);
    n = n + 1;
}

// --- 4. Switch-Case-Default 分支 ---
switch (status) {
    case 1:
        print("运行中");
        break;
    case 2:
        print("已暂停");
        break;
    default:
        print("未知状态");
}

3. 函数、一等公民闭包与 FFI

函数使用 fun 关键字定义，支持类型化参数、返回值（return 或 ret）。匿名函数可作为一等公民在变量间自由传递。同时支持直接链接 Windows 原生 DLL 动态库（FFI）。 

// 具名函数定义 (支持参数类型限定)
fun add(a: int, b: int) {
    return a + b;
}

// 匿名函数 (Lambda) 与高阶函数闭包
var makeMultiplier = fun(factor) {
    return fun(x) {
        return x * factor;
    };
};

var doubleFn = makeMultiplier(2);
print("Double 15: " + doubleFn(15)); // 输出: 30

// 原生动态链接库 Native FFI 声明
native fun MessageBoxA(hwnd: ptr, text: string, title: string, uType: int)
  (dll="user32.dll", fun="MessageBoxA", prototype="WINAPI");

4. 面向对象编程 (OOP) 核心

支持类声明、单继承（extends 或 : 语法）、构造函数级联 super()、成员访问控制修饰符（public、private、protected）、静态方法（static fun）与抽象方法（abstract fun）。 

// 基类定义
class Vehicle {
    protected var string brand;
    protected var int speed;

    Vehicle(brand, speed) {
        this.brand = brand;
        this.speed = speed;
    }

    public fun accelerate(delta) {
        this.speed = this.speed + delta;
        print(this.brand + " 当前时速: " + this.speed + " km/h");
    }

    public static fun getStandardUnit() {
        return "km/h";
    }
}

// 子类继承与父类构造链
class ElectricCar extends Vehicle {
    private var int batteryLevel;

    ElectricCar(brand, speed, battery) : super(brand, speed) {
        this.batteryLevel = battery;
    }

    public fun charge() {
        this.batteryLevel = 100;
        print(this.brand + " 电池已充满 100%!");
    }
}

var tesla = new ElectricCar("Tesla Model 3", 80, 45);
tesla.accelerate(20);
tesla.charge();
print("标准单位: " + Vehicle.getStandardUnit());

6. 结构化异常处理与模式匹配

提供 try-catch 块和 throw 语句。通过强大的 in 关键字可在捕获异常时实现结构化类型匹配判断。 

import "core/Error.tzd";
import "core/DatabaseConnectionError.tzd";

fun queryDatabase(queryStr) {
    if (queryStr == "") {
        throw new DatabaseConnectionError("SQL语句不可为空", "ERR_DB_EMPTY");
    }
    return "Query OK";
}

try {
    queryDatabase("");
} catch (err) {
    // 使用 in 操作符检查具体异常类型
    if (err in DatabaseConnectionError) {
        print("[数据库异常] " + err.message + " (" + err.code + ")");
    } else {
        print("[系统异常] " + err);
    }
}

7. 原生 LibTorch 深度学习标准库

TzdLang 将深度学习作为语言一等公民，提供与 Python PyTorch 体验一致、底层完全由 C++ SIMD/GPU 硬件加速的张量计算与神经网络架构。 

import "torch/All.tzd";

// 1. 张量创建与数学运算
var t1 = torch_tensor(1.0, 2.0, 3.0, 4.0);
var t2 = torch_reshape(t1, 2, 2);
var mulRes = torch_matmul(t2, t2);
print("矩阵乘法结果: " + torch_to_string(mulRes));

// 2. 自定义神经网络模块
class ConvClassifier extends Module {
    var layer1;
    var layer2;

    ConvClassifier() {
        super("ConvClassifier");
        this.layer1 = new Linear(128, 64);
        this.layer2 = new Linear(64, 10);
        this.registerModule("l1", this.layer1);
        this.registerModule("l2", this.layer2);
    }

    fun forward(x) {
        var h = torch_relu(this.layer1.forward(x));
        return torch_softmax(this.layer2.forward(h), -1);
    }
}

var net = new ConvClassifier();
var logits = net.forward(torch_randn(8, 128));

// 3. 损失函数计算与权重持久化
var lossFn = new CrossEntropyLoss();
var targets = torch_randint(0, 10, 8);
var loss = lossFn.forward(logits, targets);
print("交叉熵 Loss: " + torch_scalar_value(loss));

// 保存模型权重二进制快照
net.save("my_checkpoint.bin");

8. 原生多线程并发库 (Thread)

支持直接由系统内核调度的轻量级多线程，利用 C++ std::thread 底层实现真正的多核心并行处理。 

import "thread/Thread.tzd";

fun heavyComputeTask() {
    var sum = 0;
    for (i = 0; i < 500000; i++) {
        sum = sum + i;
    }
    print("线程计算完成，总和: " + sum);
}

// 创建并启动并发线程
var thread = new Thread(heavyComputeTask);
thread.start();

// 主线程继续工作
print("主线程正在执行其他任务...");

// 等待工作线程结束
thread.join();
print("所有线程已安全汇合。");
Code Style & Best Practices

语言标准编程规范手册

为保障 TzdLang 工程代码的可读性、稳定性与 JIT 执行效率而制定的官方编程规范

规范 1：标识符与命名准则

• 类名 / 枚举名：采用 PascalCase（如 MatrixSolver, ThreadRunner）。
• 函数 / 方法 / 变量：采用 camelCase（如 computeGradient(), batchSize）。
• 全局常量 / 枚举项：采用 UPPER_SNAKE_CASE（如 MAX_BUFFER_SIZE, Color.RED）。
• 源码文件：脚本采用 snake_case.tzd，类模块推荐 PascalCase.tzd。

规范 2：代码排版与格式风格

• 缩进：统一使用 4 个空格，禁止混用制表符 Tab。
• 大括号规则：采用 K&R (Egyptian) 风格，即左大括号 { 紧随语句末尾同行，右大括号独立占行。
• 语句结尾：每条语句末尾必须显式添加分号 ;。

规范 3：For 循环严格语法防坑

• 核心避坑禁令：for 循环头部严禁使用 var 或类型前缀！
• 推荐写法：for (i = 0; i < n; i++) { ... }。
• 原理：TzdLang 词法与语法分析器将循环头部的首个子句特化为变量赋值表达式，带类型前缀将导致语法歧义报错。

规范 4：面向对象设计准则

• 字段显式声明：所有成员变量必须在类体头部集中声明（如 var int id;），避免动态注入隐式属性。
• 构造函数父级调用：子类构造函数必须通过 : super(...) 语法显式触发父类构造，确保继承链完整。
• 链式调用：具备连贯调用语义的方法（如 Builder 模式）必须在最后显式 return this;。

规范 5：防御式异常处理最佳实践

• 禁用裸字符串抛出：严禁使用 throw "error"，必须继承并抛出 new Error(message, code)。
• 类型甄别保护：在 catch(err) 块中必须通过 if (err in SpecificError) 进行精细化错误过滤，并妥善处理兜底分支。

规范 6：JIT 友好型高性能编码指南

• 循环内杜绝无谓堆分配：在密集循环体中避免频繁 new 对象或拼接复杂字符串，善用预分配。
• 标量递归加速：递归函数参数尽量保持双精度浮点数或整型，以便 JIT 引擎自动生成 worker_native 双精度原生专用函数。
• 善用向量化张量：大规模矩阵与数组运算优先调用 torch_* 向量算子。

Internal Working Principles

编译器与运行时底层工作原理

解密 TzdLang 是如何将高级动态代码编译优化为超越 HotSpot 性能的原生机器码

全链路执行流水线 (Execution Pipeline)

1

词法分析与语法树生成 (ANTLR4 Frontend)

基于 TzdLang.g4 文法文件，词法分析器（Lexer）将源码转化为 Token 流，语法分析器（Parser）构建具体的抽象语法树（AST），提供 Visitor 遍历模式支持。

ANTLR4 C++ ParseTreeVisitor AST Generation
2

Tier 0: 字节码虚拟机 (TzdBytecodeVM)

代码初次运行时由编译器直接下发为堆栈式字节码指令（OpCodes），在虚拟机中即时执行。具备多态内联缓存（PIC）与 .tzdc 紧凑二进制格式序列化能力，零冷启动延迟。

Stack VM Inline Caching .tzdc Binary Cache
3

热点探测器 (Hotspot Profiler)

运行时引擎追踪函数调用计数（阈值 50 次）与循环回边计数（阈值 1000 次）。一旦达到阈值，将该函数提交至异步 JIT 编译队列，主线程继续执行毫无卡顿。

Invocation Count >= 50 Backedge Count >= 1000 Thread Safe
4

Tier 1: 异步 LLVM ORC JIT 编译与优化

后台编译线程池利用 LLVM ORC JIT 将 AST 转化为 LLVM IR，执行内联优化（AlwaysInlinerPass）、mem2reg、公共子表达式消除（EarlyCSE）与死代码剔除（DCE），生成高度优化的 x86_64 机器码。

LLVM ORC JIT mem2reg worker_native Direct Dispatch

JIT 关键黑科技与优化技术

⚡ 无装箱原生 Double Worker 派生

为热点函数生成 double worker_native(ptr, double...) 签名，自递归调用直接传递 64 位浮点原生寄存器，彻底消除 TzdValue 堆栈装箱、参数数组动态分配与 rt_to_double_fast 转换开销。

🚀 硬件整除指令特化 (FPToSI + SRem)

在数值取模 % 运算中，TzdLang 识别整数上下文，将其特化为 LLVM FPToSI + SRem 单条硬件 idiv CPU 指令，彻底取代 C 标准库 fmod() 沉重的外部函数跳转开销。

🔍 ReadOnly 属性驱动的循环不变量外提 (LICM)

对象字段读取 rt_tzd_get_member 被标记为 ReadOnly。LLVM 的 CSE 与 LICM（Loop Invariant Code Motion）优化 pass 能够智能识别循环内不变的属性读取，将其直接提至循环体外只执行一次。

🛡️ 分代三色标记 SATB 垃圾回收

新生代采用 BumpPointerArena 64KB 块连续内存指针碰撞分配，释放时整块销毁；老年代在标记阶段配备 SATB 写屏障，在覆盖对象槽位前截获旧指针写入快照队列，完全杜绝并发漏标与悬垂指针。

GitHub Pages 一键部署指南

仓库已内置自动化发布流水线与静态源文件，您可以通过以下任意一种方式在 GitHub 上一键部署此网站！

方式一：GitHub Actions 自动流水线 (推荐)

本仓库已在 .github/workflows/deploy-pages.yml 中配置了官方推荐的 GitHub Pages 自动部署流程。

  1. 将代码推送到 GitHub 仓库的 master 或 main 分支。
  2. 进入 GitHub 仓库页面，点击 Settings (设置) > Pages。
  3. 在 Build and deployment > Source 下拉框中，选择 GitHub Actions。
  4. 提交或手动点击 Actions 中的“Run workflow”，网站将在 30 秒内全自动部署上线！

方式二：直接绑定 /docs 目录 (免 Actions)

由于网站全部静态资源均已规范保存在 docs/ 目录中，您也可以无需等待 Actions 构建直接发布：

  1. 打开 GitHub 仓库中的 Settings > Pages。
  2. 在 Source 中选择 Deploy from a branch。
  3. 在 Branch 选择 master 分支，目录选择 /docs。
  4. 点击 Save (保存)，稍等片刻即可获得公开访问链接（如 https://tzdwindows.github.io/TzdLanguage/）！
